# PD2304（vivo iQOO 11S / V2304A）

本仓库在 [Kirk Lin](https://github.com/kirklin/skyward) 的 Skyward 之上加入 PD2304 的移植。
与上游的差异只在这些地方：

- `devices/pd2304.toml` —— 设备配置
- `libs/pd2304/` —— 恢复环境缺少的共享库
- `build.sh` —— 构建脚本
- `crates/` 里的移植改动（见 `git log` 的 `port:` 提交）
- `docs/pd2304.md` —— 本文

## 设备

| 项目 | 值 |
| --- | --- |
| 机型 | iQOO 11S（V2304A） |
| 代号 | PD2304 |
| 平台 | SM8550（kalama），第二代骁龙 8 |
| 屏幕 | 原生 1440 × 3200，density 640 |
| 系统 | Android 16 / OriginOS 6 |
| 固件 | 16.3.13.5.W10 |
| 分区 | A/B + 动态分区（super） |

已验证：显示（原生 1440×3200@144）、触摸、震动、FBE 解密、super 动态分区挂载、
WLAN（连接 / DHCP / 无 DNS 热点的联网探测）、EFS 备份（modemst1、modemst2、fsg、fsc、persist + SHA-256 清单）。

## 构建

依赖：

- Rust（版本见 `rust-toolchain.toml`）与 `aarch64-linux-android` target
- [`cargo-ndk`](https://github.com/bbqsrc/cargo-ndk)
- Android NDK（r29 实测可用）
- `lz4` 命令行工具（打包器用它压缩 ramdisk）

```bash
export ANDROID_NDK_HOME=/path/to/android-ndk-r29
cargo install cargo-ndk --locked
./build.sh            # → out/skyward-pd2304.img
```

Windows 上装在 WSL 里构建；仓库在 Windows 盘（`/mnt/c`）时编译会慢很多，建议先把源码拷进
Linux 文件系统再编。

## 底包

构建需要原厂 `recovery` 分区镜像（整段，带 AVB footer），从官方全量包的 `payload.bin` 里取：

```bash
payload-dumper-go -p recovery payload.bin -o stock
# 放到 stock/pd2304/recovery.img
```

`stock/`、`out/` 已被 `.gitignore` 忽略，仓库不提供原厂镜像。

## 刷入与回滚

```bash
fastboot getvar current-slot
fastboot flash recovery_<slot> out/skyward-pd2304.img
fastboot reboot recovery
```

回滚：把原厂 recovery 分区镜像刷回同一槽位。
要求 Bootloader 已解锁；首次进入后按提示输入锁屏密码解密 data。

## 恢复环境缺少的库（`libs/pd2304/`）

都是**本机自身**固件里的文件，正常开机由系统提供，恢复环境不挂载 APEX / 系统分区时缺失：

| 库 | 谁需要 |
| --- | --- |
| `android.hardware.security.keymint-V2-ndk.so` | vendor 的 KeyMint 服务 |
| `android.hardware.security.secureclock-V1-ndk.so` | 同上（注册 `ISecureClock`） |
| `android.hardware.security.sharedsecret-V1-ndk.so` | 同上（注册 `ISharedSecret`） |
| `libcurl.so` | `ssgtzd`（vivo 把它放在 system 分区） |
| `libfmq.so` | `libqcc_sdk.so` → `ssgtzd` |

## 移植时踩到的坑

1. **`libfmq.so` 缺失**：`ssgtzd` 每秒退出一次，日志是
   `CANNOT LINK EXECUTABLE "/vendor/bin/ssgtzd": library "libfmq.so" not found`。
   补上后 KeyMint + Gatekeeper + ssgtzd 整条解密链才通。

2. **显示模式**：内核 DSI 连接器的首选模式是 1080×2400，面板原生是 1440×3200。
   原实现只认首选模式，按 1440 配的 density 会把界面画成 270dp，字变大、解密页超出画布被裁。
   `KmsSurface::open` 现在会按 `[display] width/height` 匹配连接器模式（同尺寸先设慢档再切最快档），
   面板没有该尺寸时回退首选模式。

3. **热点不给 DNS**：部分热点（如 Windows ICS）的 DHCP 只发地址和网关、不发 option 6，
   联网探测会报 `the network gave no DNS server`。现在租约没有 DNS 时回退到恢复环境自带的
   `/etc/resolv.conf`。

4. **底包格式**：官方 `recovery.img` 是 boot header v4、ramdisk 用 LZ4 legacy、结尾带 AVB footer，
   且 `kernel_size = 0`（内核在 `boot` 分区）。打包器只改 ramdisk，其他保持原样。

5. **binder 标记**：vivo 的 recovery ramdisk 带系统版 libbinder，服务目录只认其中一种头部标记；
   启动时探测两种标记（`choose_header`）。

6. **ADSP 固件被 vendor 分区挡住**：init 把 modem 挂到 `/vendor/firmware_mnt` 后，Skyward 再把 vendor
   挂到 `/vendor`，加载 ADSP 时 `adsp.b11` 不可见，充电驱动不 probe，状态栏没有电量和温度。
   现在启动时先按 `[firmware] partition = "modem"` 把 modem 挂到 `/firmware`（真实目录，替换 init
   留下的符号链接），再通知 init 拉起 ADSP。
